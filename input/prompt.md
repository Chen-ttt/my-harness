已完成的原阶段 1 与原阶段 2 的 Loop 成果直接沿用，不重学。A–E 是新计划编号；周数是时间预算，阶段结束以验收为准，不是面试达标保证。

以下是阶段范围与验收规格，不记录完成状态；只在 progress.md 展开当前阶段的执行清单。

### A：最小可靠运行时（2 周）

- 完成工具注册与参数契约：消除 schema/impl 漂移，完整 params 传递，区分缺字段与合法的 0/false/空串，并检查类型。
- 拆分错误与终止原因，明确模型请求重试、参数纠错与工具执行失败的不同处理；补退避、预算和对应失败实验。
- 加入轮数/时间/Token 预算与超时取消；验证慢请求或工具不会仅靠轮数限制而无限等待。
- 最小 Trace：按任务、轮次和工具记录状态、耗时、重试、usage、错误与结果引用，从 roundLogs 起步。
- 选择小型 JS/TS 测试仓库，先实现只读定位/分析任务，定义首批输入与判定规则。
- 验收：沿一条失败轨迹讲清做了什么、哪里失败、为何结束、是否能继续；独立完成一个超时或取消实验。

### B：状态与恢复（2 周）

- 区分 messages、任务状态、工具执行记录和审批状态，设计最小持久化及恢复协议。
- 学习必要的原子更新、事务/唯一约束与幂等；用文件或 SQLite 验证，不强制引入中间件。
- 在可丢弃仓库加入受限修改和测试执行，明确授权、工作目录、进程退出与资源清理边界。
- 验证不同中断位置，重点处理“工具成功但本地未记录”的结果未知状态；不能盲目重试有副作用操作。
- 验收：杀进程后恢复；展示状态、审批与外部结果如何核对，并解释不能自动恢复时的处理方式。

### C：上下文与工具策略（3 周）

- 实现上下文预算、工具大结果裁剪/外置、摘要、结构化 todo/plan/事实保留、Skill 按需加载。
- 最小跨会话 Memory：一种存储/召回方案即可，说明来源、冲突、过期与隔离；复杂混合检索不作为本阶段前置条件。
- 完成实验一：原始工具输出 vs 规则裁剪 vs 结果外置后按需读取（按实际失败选择必要方案）。
- 开始实验二：最近消息窗口 vs 摘要 vs 结构化任务状态加有限历史，关注目标、约束、事实和工具消息配对。
- 验收：至少一组完整对照实验，能展示收益与退化案例，而不只是展示功能可运行。

### D：效果优化闭环（2 周）

- 回归集从少量逐步扩充到 20–50 条，覆盖边界/回归案例；重复运行与独立任务覆盖分别统计。
- 对需要语义评审的部分校准 Judge，结合人工复核；区分复测一致性与正确性。
- 完成第二项优化实验及复盘，必要时继续 C 的实验二；不预设复杂策略一定有效。
- 争取在工作中参与“Benchmark 发现问题→修改 Harness→回归”的真实闭环；机会未落实时继续练手实验，不将其标记为生产成果。
- 历史 reasoning_effort 全维度实验按归因需求选做；不再强制 low/high/max 各 3 次作为结课条件。相关假设若被采用，应记录配置、重复次数与局限。
- 验收：两份“失败案例→假设→实现→固定任务/配置/预算的对照→重复运行→归因→适用边界”复盘，报告成功率、耗时、Token/成本与失败类型。无收益或退化也可形成合格结论。

### E：岗位专项与模拟（1 周）

- 整理一个主要开源实现的 Loop、工具、上下文和恢复链路，对照自己的取舍；阅读在 A–D 期间持续进行。
- 用一个现有工具实现 MCP Server 接入并比较直接调用；可在 A–D 主线稳定后穿插，控制范围。
- 整理真实工作与练手项目的职责、证据和边界，结合前端经历练习项目表达。
- 完成完整模拟面试（设计、编码、效果验证）并记录缺口；主语言与基础算法训练从 A 开始。
- 根据实际投递目标补专项。若重点投腾讯，再补其 MySQL/Redis/Pulsar 要求；不为全部 JD 预先扩张范围。
- 验收：能接住实现、失败模式与实验依据的追问；模拟成绩不直接外推为真实面试覆盖率或通过率。


【重点实验与评测标准】

1. 工具结果如何进入上下文：比较原始输出、规则裁剪、结果外置后按需读取，观察丢失信息与任务质量。
2. 长任务如何保留关键信息：比较最近消息窗口、摘要、结构化任务状态加有限历史，关注目标、约束、事实与工具调用配对。

每项实验先记录失败案例、原因假设、判定规则，再固定任务集、模型配置与预算做对照和重复运行。报告任务成功率、耗时、Token/成本及失败类型，说明收益、退化、样本量与适用边界。先用少量任务打通流程，再逐步扩充到 20–50 条；同一任务重复运行不等于增加任务覆盖。无法确定性判定的质量用 Judge，并用人工复核校准；复测一致性不等于正确性。

【掌握标准】

不以“精通”作不可检验的目标。核心标准：能独立实现、解释取舍、构造失败案例，并用证据评价效果。
