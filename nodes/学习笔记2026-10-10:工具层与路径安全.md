# 一、核心知识点(高频必考,必须能脱稿讲)
## 1.工具错误为什么「返回文本」而不是「抛异常」★★★
- 未捕获 Promise rejection 会杀死进程 →一次坏参数毁掉整个会话(状态/token/结果全丢)
- 工具执行层是 harness 的故障隔离边界:契约是「永远 resolve 为 string,永不 reject」
- 错误文本是模型的纠错信号:质量决定模型是修正还是瞎试。ENOENT/EISDIR/EACCES 要有区分度
- 纵深防御(defense in depth,即多层设防):工具层 catch 已知错误给上下文,loop 层再兜底接漏网的——任何一层失守都不致命,两层都要有

## 2.Prompt Injection 与威胁模型 ★★★
- 直接注入(用户输入)vs 间接注入(网页/文档/工具结果/RAG 夹带指令)vs Jailbreak(绕模型安全策略)——三者常被混问
- 完整攻击链路举例:仓库 README 埋指令 →模型读文件是正常操作 →恶意文本进上下文 →模型"尽职"调用工具 →私钥外泄
- LLM 无法像编译器区分代码与数据那样区分指令与外部数据(Context Mixing)
- 只读工具也要拦:目录结构、错误码差异(ENOENT vs EISDIR)本身就是情报

## 3.代码边界 vs System Prompt ★★★
- prompt 遵循是概率行为(上下文膨胀、注入都会降低遵循率);代码检查是确定性行为
- "请勿访问敏感路径"写在 system prompt 是请求,写在 path.resolve 检查里才是边界
- 口试金句:"模型可以提议,但不能自行决定权限"——模型不是安全主体
- 推广到自己的 benchmark:安全属性必须做成确定性用例,不能做成统计用例

## 4.路径安全三连 ★★★
- 前缀绕过: /proj-secret 以 /proj 开头,startsWith 会误放行 →比较必须写成 startsWith(root + path.sep) (即 /proj/),且单独放行 resolved === root (模型传 "." 时 resolve 结果就是 root,列目录是合法操作)
- 绝对路径: path.resolve(root, p) 有个特性——第二个参数若以 / 开头(绝对路径),会直接采用它、忽略第一个参数 root。所以模型传 /Users/pipi/.ssh/id_rsa 也能溜进来,绝对路径同样是攻击入口
- 符号链接:path.resolve 是纯字符串运算,fs 才物理跟随链接——词法 guard 挡不住"传送门"(fakelink 实验:guard 看到的和 fs 打开的不是同一条路径)

## 5.词法 + realpath 双检查串联(guard 的正确形状)★★★
「双门」= guard 里先后两道检查:第一道只算字符串,第二道要读磁盘。

> 第一道·词法检查(纯字符串运算,零 I/O):拦截明显越界的路径
> → 第二道·realpath 检查(读磁盘,把符号链接展开成真实路径,再查一次边界)

- 两道检查串联(AND 语义):任一否决即拦截。 || 并联 = 第一道放行就整体放行,且短路求值会让第二道根本不执行(实操踩过: resolveInRoot(p) || resolveInRoot(realPath) ,第一个 truthy 后第二个压根没跑)
- 单点收口:安全检查集中在 guard.mjs 一处,散落在各工具 = 忘一个漏一个
- 顺序不可换:realpath 在前会让越界路径报 ENOENT(语义撒谎+安全退化)

## 6.三个错误分支的语义决策 ★★★
- ENOENT(路径不存在)→放行词法路径:链接攻击需目标真实存在才成立,故不开洞;"不存在"由 fs 去报才诚实(拼写错误 ≠ 越界,模型纠错方向才对)
- EACCES 等(权限等异常)→ throw(fail closed):查不了就拒绝,绝不默认放行
- 成功 → 返回 realpath 展开后的路径,而非 resolve 拼出的词法路径:缩小 TOCTOU 窗口
- 错误消息最小泄露:不透露 root 外真实路径(错误消息也是输出面/攻击面);只回显模型自己传的参数

## 7.TOCTOU ★★☆
- Time-of-Check to Time-of-Use:检查和使用之间,链接被替换的竞态
- 我们的取舍:返回已展开的真实路径,后续 fs 调用不再跟随链接,竞态窗口被压缩到两次调用之间;残余风险明确接受(彻底修复需 openat/dirfd 系统调用,业界普遍也这么取舍)——知道自己在接受什么是考点加分项

## 8.沙箱的层级认知 ★★☆
- 今天做的是最小形态:文件系统只读白名单(workspace root)
- 业界完整沙箱还有:写隔离、shell/进程隔离、网络出口管控、容器/微 VM;单一隔离不够,必须组合
- 权限系统(高风险操作人工审批)是另一条线,Claude Code 等真实 harness 均内置

# 二、重要工程素养(项目追问时体现,理解即可不用背)
1. 断言来自规格,不是实现——两次实操教训:SUCCESS 字面量测试、越界报 ENOENT 被断言迁就。规格不动,实现去够规格
2. 漏洞 → 回归测试:攻击路径先写成测试,修复后把断言反转(原来断言"能读到私钥",修复后断言"报越界"),从此永久看守(test-tool.mjs 实验 9)
3. 测试环境自建自清:测试需要的临时环境(术语叫 fixture,指符号链接、临时目录这类前置条件)由测试自己创建、自己清理——开头创建,try/finally 里删除,断言炸了环境也必清;测试不绑架外部环境
4. 测试不依赖启动姿势:相对路径按启动目录解析(启动目录变了,同一脚本的 ../x 指向不同地方)→用 import.meta.dirname 锁定模块自身所在目录;flaky test(时好时坏、不稳定重复的测试)的一个经典来源就是环境依赖
5. guard 为什么必须 async:realpath 是磁盘 I/O → fs/promises 返回 Promise;realpathSync 阻塞事件循环,常驻 loop/并发场景是毒药。接口形状(同步/异步)是承诺,改动波及所有调用方
6. join("\n")背后的原则:工具输出是给模型的数据,可解析性优先(macOS 文件名可含逗号,逗号连接会歧义)——细节是 API,原则是考点
