# 后端基础：从 Node.js 脚本到可靠的小服务

## 起点与目标

我熟悉 JavaScript 和前端开发，想理解一个程序离开浏览器后，如何接收请求、执行任务、保存状态，以及在出错后恢复。以技术探索为目的，用熟悉的语言建立直觉，再用小实验检验。

主技术栈：JavaScript / TypeScript、Node.js 标准库、HTTP / SSE、SQL / SQLite。辅助工具：curl、终端、node:test。Redis、消息队列、容器只作为后续选读。

先用 `.mjs` 降低环境成本；遇到数据结构再补 TypeScript 类型。开始实验前记录 Node.js 版本，按对应版本查 API。SQLite 可以先用命令行；选择 Node 驱动时再核对版本支持，不为了开始学习先搭建服务框架。

## 如何使用

- 每次 15–25 分钟，只推进一个编号；同一行的两个问题依次问，第二问用于检验理解。
- 每次先回忆 2 分钟，再讨论一个机制，最后预测一个小例子的结果。只有 5 分钟时，做回忆或追问即可。
- 每个模块结束可做一次 20–40 分钟的小实验；可以拆开，不要求每天写代码。
- 能用自己的话解释机制、预测一个变化后的结果，就可以前进。看过答案不等于掌握；卡住时只补当前依赖。
- 按 B01–B38 推进；不强制日历期限。若与其他主题并行，交替安排即可。

## 1. Node.js：执行模型

| 编号 | 原子知识点 | 依次提问 |
|---|---|---|
| B01 | 进程与内存 | Node 程序启动后，变量存在哪里？→ 程序退出再启动，哪些东西还在？ |
| B02 | 事件循环与阻塞 | 一段耗时同步计算为什么会拖慢其他请求？→ 把它包进 async 函数会改变什么？ |
| B03 | Promise 与等待 | await 暂停的是当前函数还是整个进程？→ 两次 await 与 Promise.all 的启动顺序有什么不同？ |

掌握标准：画出两个异步任务的时间线，指出同步阻塞位置；能解释并发不等于 CPU 并行。

小实验：用定时器模拟 6 个任务，对比串行、全部并发、上限为 2 的执行顺序。暂不钻研事件循环所有阶段与微任务排序题。
