# 源码阅读：沿着 Pi 的一次执行理解 Agent

## 起点与目标

我熟悉 JavaScript，想理解一个真实 Agent 如何把消息、模型请求、工具执行和上下文管理连接起来。以 Pi 为唯一主线，先追踪具体执行，再讨论抽象和设计取舍。

选择它的理由：核心使用 TypeScript，循环、工具和事件有明确入口，能够从较小的运行时模块逐步走向完整应用。无需先通读整个仓库，也不必先完成另一套课程。

阅读基线：2026-10-22 核对的提交 `be14d9732f98fcc33929cf103a92b96afaa6523e`。旧地址 `badlogic/pi-mono` 已重定向到 [earendil-works/pi](https://github.com/earendil-works/pi)。本计划的路径与符号以此提交为准；学习时固定版本，升级时另记差异。

[固定版本目录](https://github.com/earendil-works/pi/tree/be14d9732f98fcc33929cf103a92b96afaa6523e)。下文路径均相对此仓库，不是本地项目路径。教学伙伴应实际读取对应版本再解释；无法取得源码时，请我提供对应片段，不根据函数名猜实现。

## 每次怎样读

每次 15–25 分钟，一节只读一个编号；一行中的问题依次讨论，时间不够就在中间停。建议顺序：回忆上次结论 → 找入口与数据 → 预测行为 → 阅读分支验证 → 留下续学卡。

只读当前函数及必要的直接调用。大型文件用符号定位，不整份塞进上下文。遇到不懂的类型、语法或运行时机制，补充一个最小例子后回到原链路。

每次留下三项：输入输出、关键分支、源码证据（版本＋路径＋符号）。条件允许再读一个相关测试或运行本地替身实验。静态推演、读过测试、实际运行要分别记录。

## 第一条线：用户输入如何得到一次模型响应

路径简称：

- A：`packages/agent/src/agent.ts`
- L：`packages/agent/src/agent-loop.ts`
- T：`packages/agent/src/types.ts`
- 核心测试：`packages/agent/test/agent.test.ts` 与 `packages/agent/test/agent-loop.test.ts`

| 编号 | 原子主题 | 先读哪里 | 依次提问 | 本节产物 |
|---|---|---|---|---|
| S01 | 包的边界 | `packages/agent/src/index.ts`，再定位 A 的 `Agent` | 这个包暴露了哪些能力？→ 哪个入口接收一条用户输入？ | 一张不超过 5 个节点的入口图 |
| S02 | 消息与状态 | T 的 `AgentMessage`、`AgentContext`、`AgentState` | 一条消息最少带哪些信息？→ 对话内容和运行中的状态分别放在哪里？ | 两类数据的对照例子 |
| S03 | 启动一次执行 | A 的 `prompt`，沿调用进入 L 的 `runAgentLoop` | prompt 做完什么准备才进入循环？→ 初始消息何时进入上下文？ | 标出参数传递和第一次状态变化 |
| S04 | 一轮与多轮 | L 的 `runLoop` | 什么是一轮，什么是一次完整执行？→ 没有工具调用和后续输入时在哪里结束？ | 一条最短成功路径 |
| S05 | 请求边界 | L 的 `streamAssistantResponse`，T 的 `StreamFn` | 哪个对象真正交给模型调用？→ 如何替换模型调用来观察循环？ | 输入、输出与替身接口 |
| S06 | 流事件 | L 的 `streamAssistantResponse`，T 的 `AgentEvent` | partial 与 final 消息分别何时写入？→ UI 看到的增量事件与最终消息有何区别？ | 一段事件时间线 |

阶段停点：不看文件，能讲清“输入 → 循环 → 模型流 → 消息更新 → 结束”，并指出每一步的证据。先忽略 CLI、终端渲染和不同模型供应商的适配。

## 第四条线：会话如何保存、再被读回来

这一段可在熟悉文件读写之后再学。源码中的会话记录与另一个系统的任务恢复，不预设为同一种保证。

统一入口：`packages/coding-agent/src/core/session-manager.ts`。

| 编号 | 原子主题 | 先读哪里 | 依次提问 | 本节产物 |
|---|---|---|---|---|
| S19 | 记录格式 | `SessionHeader`、`SessionEntryBase`、`SessionEntry` | 一条持久化记录比一条模型消息多了什么？→ id 和 parentId 分别用来表达什么？ | 三条记录构成的小树 |
| S20 | 写入与读取 | `SessionManager` 中沿记录写入调用定位；`loadEntriesFromFile` | 记录在何时写入文件？→ 最后一行不完整时，读取路径怎样处理？ | 写入边界及对应错误分支 |
| S21 | 上下文投影 | `buildSessionProjection`、`buildSessionContext` | 存在文件里的记录是否都直接发给模型？→ 如何从选定分支与压缩记录构造当前上下文？ | 存储记录到请求消息的映射 |
| S22 | 保证的边界 | 回看 S08、S20，对照相关测试 | 工具已经影响外部世界、记录尚未写入时退出会怎样？→ 读回对话是否足以保证外部操作只执行一次？ | 源码已保证、未保证、尚未确认三栏 |

相关测试目录：`packages/coding-agent/test/session-manager/`，优先找 `save-entry.test.ts`、`load-entries.test.ts`、`build-context.test.ts`。先确认测试具体覆盖了什么，再判断能否支持自己的结论。

阶段停点：能从一份小会话记录还原消息路径，并明确“恢复上下文”和“恢复外部副作用”的区别。
